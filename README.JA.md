# Pico2W DualSense 5 Bridge — OLED Edition

[English](README.md) · [中文](README.CN.md) · [Deutsch](README.DE.md) · [Español](README.ES.md) · [Français](README.FR.md) · **日本語** · [Português (Brasil)](README.PT-BR.md)

> Raspberry Pi Pico2W を DualSense（DS5）コントローラー用のワイヤレスアダプターにします。オンボードのステータス表示もオプションで使えます。

> **OLED Edition** は **[awalol/DS5Dongle](https://github.com/awalol/DS5Dongle)**（アップストリーム）のフォークです。Pico-OLED-1.3 128×64 ディスプレイアドオン（オプション）に対応し、11 の画面（ステータス、4 スロットの複数コントローラーペアリング、お気に入りとエフェクトプリセット付きのライトバーカラーピッカー、トリガーテスト、ジャイロ傾き、タッチパッド、診断、CPU／クロック、BT 信号強度、オーディオ VU メーター、保存される設定メニュー）と、DS5 のボタン組み合わせによるソフトリブートを追加しています。コアのブリッジファームウェアはアップストリームが正式なソースです。このフォークはアップストリームに追従し、その上にアドオン機能を重ねています。

> **🧪 最新の機能を試したいですか？開発チャンネルをお試しください。** アプリで **アプリ設定 → アップデート → 開発版** を選びます（先に確認があります。**安定版に戻す** でいつでも戻れます）。開発版も変更のたびに安定版と同じ自動テストを通ります。安定版はさらに、実機と Windows でのリリースチェックと、日常での使用期間を経ています。現在の **0.9.5-dev.20**（リリース候補 2）で安定版 0.9.4 から追加された内容：
>
> - **DualSense Edge：** Fnボタンと背面ボタンの割り当て変更、PlayStation Accessories の Edge のカスタムプロファイル、専用のコントローラー図と OLED 表示
> - **スティック：** 感度曲線とスティックテスト
> - **コントローラーのマイク：** マイクレベルの調整、エコーキャンセル、ミュートランプがミュートに連動。PC のミュートとマイク音量がコントローラーに届きます
> - **スリープと復帰：** PC がスリープするとコントローラーの電源が切れ、PSボタンで PC を復帰できます
> - **ゲーム（Linux）：** ゲームごとに好きな Proton バージョンを選択、HDR の設定、XInput 専用ゲームでもコントローラーを認識
> - **アプリから OLED を操作：** ライブ画面の横に KEY0/KEY1 とコントローラーのボタン、さらに **OLED を共有**（PNG、クリップボード、GIF）
> - **コントローラーのファームウェアチェック** とコントローラーの状態情報
> - **ヘッドセット（Linux）：** コントローラーにヘッドセットを挿すとステレオに、抜くとスピーカーに戻ります
> - **ボードでペアリング：** OLED に *Press PS to connect* と表示。KEY0 を 2 秒長押しでペアリング（カウントダウン付き）。待機中に検索し続けません
> - **すべてのメッセージが 7 言語に対応**

必要なのはこのアプリだけです。各リリースには対応するファームウェアが含まれており、アプリが Raspberry Pi Pico 2 W にインストールし、最新の状態に保ち、すべてを設定します：

3. コントローラーをペアリングします：ライトバーが点滅するまで **PSボタン + クリエイトボタン** を長押しします。接続されるとアプリに表示されます。

- **ゲーム：** Steam、Heroic、Lutris のライブラリ（Windows：Steam、GOG Galaxy、Epic）をリストとカバーグリッドで表示。ゲームごとのコントローラープロファイル（そのゲームで変えるすべてのコントローラー設定。ボタン配置とスティックの曲線も含み、コントローラー表示でライブ編集）、ゲームごとの DualSense 対応状況、そして Linux では設定の修正と DualSense 版 Proton。

## 🔄 アップデートとファームウェアのインストールはおまかせ

**アプリは自分で最新の状態を保ちます。**

- **署名付きで確認済み。** アップデートはすべて、私たちの Ed25519 鍵で署名された 1 つのフィードから届きます。有効な署名のないフィードは無視し、ダウンロードごとにサイズと SHA-256 を確認してからインストールします。古いバージョンを勝手にインストールすることはありません。
- **2 つのチャンネル：** すべての方向けの **安定版** と、最新機能の **開発版**。**安定版に戻す** で、アプリとファームウェアの両方が最新の安定版に戻ります。
- **選べます：** **アップデートを自動でインストール**（アプリが一度だけ確認します）をオンにすると、アップデートはバックグラウンドでダウンロード・確認され、次にアプリを開いたときに新しいバージョンが起動します。**アップデートを自動確認** をオフにすると、確認ボタンを押したときだけオンラインになります。
- **システムごと：** Linux では AppImage が新しいバージョンを自分の隣に置き、メニュー項目もそちらに切り替わります。Windows ではユーザーごとのインストーラーが管理者権限なしで動きます。macOS ではアップデートをリリースへのリンク付きで表示します。

**ファームウェアはワンクリックでインストール。**

- **同梱：** アプリの各リリースには、一緒にビルドしてテストしたファームウェアが入っているので、新しいボードもオフラインでセットアップできます。新しいファームウェアは同じ署名付きフィードから届きます。
- **初回セットアップ：** BOOTSEL ボタンを押しながら Pico を接続します（新品の Pico ならボタンは不要）。アプリが見つけてファームウェアをインストールします。
- **アップデート：** ボタン操作もドライブへのコピーも不要です。アプリがボードを BOOTSEL で再起動し、USB 経由でファームウェアを書き込み、再接続します。
- **書き込み前に確認：** ファイルの SHA-256 がフィードと一致し、このチップ用のファームウェアであることを確認します。確認に通らないファイルは何も書き込みません。
- **書き込み後に確認：** 新しいファームウェアが起動するのを待ちます。ボードが BOOTSEL のまま戻ってきたら、そのことを伝えて **もう一度インストール** を表示します。書き込み中は、アプリの再起動・終了・自己アップデートを行いません。
- **設定はそのまま：** 設定、ペアリング、キャリブレーション、ボタン割り当てはフラッシュの別の領域にあります。ファームウェアのビルドごとにこの領域に届かないことをチェックし、アップデートがファームウェアファイルのセクターだけを書き込むことをアプリのテストで確認しています。

## 🔬 開発とテストの方法

変更のたびに、すべての自動チェックを通します。リリースのたびに、さらにチェックを加えます。各チェックのファイル付きの完全な一覧：[docs/QUALITY.md](docs/QUALITY.md)（英語）。

**変更のたびに**

- **アプリ：** 1,800 件以上のテスト（ユニット、統合、セキュリティ）を Linux、Windows、macOS で実行。型チェック、ESLint、Prettier も。
- **ファームウェア：** ファームウェアのロジックを AddressSanitizer と UndefinedBehaviorSanitizer 付きで検証する 270 件以上の PC 上のテストと、5 種類のファームウェアビルド（Pico 2 W、Pico W、デバッグ、2 つのバリエーション）。タイミングが重要なコードが RAM から外れたり、フラッシュの設定が変わったりするとビルドが失敗します。
- **アプリのルールチェック：** Electron のセキュリティ設定、危険な HTML の禁止、色の直書きのない単一のテーマシステム、判定のない重複コードや重複ファイルの禁止。
- **判定を書面で：** 待機するループやホットパスで動くループ、すべてのエラー経路、すべてのキャッシュ、コードが確保するすべてのリソース（タイマー、リスナー、デバイス）に、判定を書いたコメントが付いています。判定のない新しいものがあるとチェックが失敗します。
- **セキュリティスキャン：** Semgrep、Gitleaks、npm audit。毎週も実行します。

**開発版のたびに**

- **UI チェッカー：** シミュレートしたボードを使う専用のアプリのコピーが、すべてのページを 7 言語・2 つのウィンドウサイズで開きます。文字の切れ、WCAG AA 未満のコントラスト、名前のないコントロールがあると失敗します。
- **リソース予算** を Linux と Windows 11 の仮想マシンで測定。
- **Windows** の仮想マシンでインストール済みアプリをテストし、GitHub Actions の実機の Mac で **macOS** のスモークテスト（ユーザーと同じ方法でインストールし、起動して操作）。

**安定版リリースの前に**

- **UI の完全チェック：** すべての画面とパネル、7 言語、両方のサイズ、すべてのテーマとスタイル、両モデルのすべてのカラー。
- **長時間の予算測定：** メモリの増加を見る 30 分間の連続テストを含め、Linux と Windows で。
- **ハードウェアのチェック：** 実際のボードと DualSense で、ライブ表示、ハプティックフィードバック、ライトバー、ボタン割り当て、スロット、トリガー、オーディオのカウンター、再起動と BOOTSEL、初回セットアップ、アップデーター、ゲームを確認。
- **日常での使用：** 開発者自身が普段使いしたうえで承認します。

**効率**

- **リリースを止める予算：** 何も変化しないページで毎秒 10 フレーム以下、表示中のアイドル時に CPU 1 コアの 2% 未満、トレイに隠した状態で 0.5% 未満、メモリ 275 MB 以下、30 分間の増加 5 MB 未満。予算を超えたら直します。上限は上げません。最新の数値：[BUDGETS.md](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Config-Web/blob/master/docs/BUDGETS.md)。

- **ファームウェア：** オーディオの経路は RAM から実行され、ファームウェアの各部分にかかる時間をアプリで確認できます。

**セキュリティと信頼**

- **署名付きフィード**（Ed25519）と SHA-256 で確認するダウンロード（上記のとおり）。
- **検証できるダウンロード：** リリースの各ファイルにはビルドの証明（attestation）があります。`gh attestation verify FILE -R MarcelineVPQ/DS5Dongle-OLED-Edition` で、このリポジトリのリリースワークフローがそのタグからビルドしたことを確認できます。
- **守りの固いアプリ：** サンドボックス化したウィンドウ、厳格な Content Security Policy、ウィンドウからのメッセージはすべて送信元を確認して検証、USB アクセスはボードと Pico のブートローダーに限定。依存関係はバージョンを固定し、公開から 2 週間以上たったものを選びます。監査：[SECURITY_AUDIT.md](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Config-Web/blob/master/docs/SECURITY_AUDIT.md)。

**アクセシビリティと言語**

- **7 言語、すべて揃っています：** どれかの言語に文字列が欠けているとテストが失敗します。コントローラーの機能名は各言語でソニーの公式名称を使います。
- **読みやすく、名前付き：** UI チェッカーがすべての言語でコントラストとコントロールの名前を確認し、どのサイズでも文字が収まる必要があります。

## 概要

このプロジェクトは Raspberry Pi Pico2W を DualSense コントローラー用の Bluetooth ブリッジとして動作させ、強化されたハプティクス対応でワイヤレス接続を可能にします。

## 機能

**コアブリッジ（アップストリームから）：**

- Pico2W 経由での DualSense の完全な接続
- HD ハプティクス（高度な振動フィードバック）
- ワイヤレス Bluetooth ブリッジ
- マイク音量によるハプティクスゲインの調整
- LED と切断時の動作を設定可能

**OLED Edition の追加機能：**

- **Linux/Proton の PC ゲームで、ボード経由のネイティブ DualSense アダプティブトリガー。** DualSense にネイティブ対応したゲームは、ボードを通じてワイヤレスでコントローラーのアダプティブトリガーを動かします。**有線接続の DualSense と 1:1 で同じ** です。Wine の `winebus.sys` #9034 の修正を含む Proton（Wine 11／現行の Proton-GE）と、Steam Input の無効化が必要です。**起動オプションは不要** です（Wine 11 は hidraw のネイティブ経路をデフォルトで有効にします）。**Steam と Heroic の両方**（Epic/GOG）で動作します。ファームウェアはボードを本物の DS5 とバイト単位で区別できないようにし、ゲームに受け入れられるようにしています（詳しくは [CHANGELOG.md](./CHANGELOG.md)）。
- Pico-OLED-1.3 ステータスディスプレイ（オプション）、**11 の画面**（ステータス、スロット、ライトバー、トリガーテスト、ジャイロ傾き、タッチパッド、診断、CPU／クロック、RSSI、VU メーター、設定）
- **ボード内のキャリブレーション（v0.9）** — スティックの中心オフセット、デッドゾーンと最大傾き半径、トリガーのストローク、ジャイロのゼロ点を、ペアリングスロットごとに、ゲームが受け取るデータに適用します（コントローラーには書き込みません）。アプリのガイド付きキャリブレーションから設定します。
- **左右別の振動の強さ（v0.9）** — 左右を個別に。ハプティックフィードバックと従来の振動の両方に適用。
- **感度曲線（v0.9.5）** — スティックごとの曲線（リニア、高精度、安定、クイック、デジタル、または 4 点のカスタム）を、ボード内でキャリブレーションの後に適用するため、すべてのゲームで使えます。ゲームのプロファイルは実行中に独自の曲線へ切り替えられます。
- **DualSense Edge 対応** — 接続時に送られるファームウェアレポートで Edge と DualSense を区別します。Fnボタンと背面ボタンはほかのボタンと同じように割り当てられ、OLED のステータス画面にも表示されます。Edge のカスタムプロファイルは Sony の PlayStation Accessories アプリで表示・保存できます（アップストリーム awalol 8a2f576。コントローラーの接続後、アプリが数秒かかる場合があります）。DS5 モードでは、アプリが失敗するファームウェアアップデートを提案しなくなりました（アップストリーム awalol ae83907）。
- **コントローラー情報（v0.9.5）** — アプリはボード経由で、コントローラー自身のファームウェアバージョン、バッテリー電圧、累計カウンターを読み取れます（読み取り専用。コントローラーのシリアル番号はアプリに届く前に消去されます）。
- **処理段階ごとの時間計測（v0.9.5）** — ボードが自身の各処理（Bluetooth、USB、オーディオ、入力、OLED、core1 のスピーカーとマイクのフレーム）の時間を計測し、アプリの **処理時間** カードに表示します。
- **OLED 画面ミラー（v0.9）** — アプリがボードの画面をピクセル単位で表示します。OLED アドオンの有無を問いません。
- **ボタンの割り当て** — 16 のデジタル操作（アクションボタン、方向キー、L1/R1/L2/R2、スティック押し込み、クリエイトボタンとオプションボタン）と DualSense Edge の Fnボタン・背面ボタンを、ほかの任意のボタンに割り当てられます。ボードに保存され、ホストがレポートを受け取る前に適用されるため、**ホスト側のソフトウェアなしで、すべてのゲームと OS で** 動作します。デフォルトは割り当てなし（そのまま）です。[設定アプリ](#️-はじめにアプリをダウンロード)の **ボタンの割り当て** ページで視覚的に、または `scripts/remap_test.py` で画面なしで編集できます。専用のフラッシュセクターに保存され、再起動後も保持されます。
- **PC のスリープと復帰（アップストリーム awalol）** — PC が 3 秒スリープするとコントローラーの電源が切れます（デフォルトでオン）。オプションで PSボタンによる PC の復帰もできます（デフォルトでオフ：コントローラーが接続されていないとき、ボードは小さな復帰専用キーボード「DS5 Dongle Wake Keyboard」として認識され、PC 側でこのキーボードによる復帰を許可する必要があります）。コントローラーが接続されているときは、これまでどおり DualSense そのものとして動作します。どちらもアプリと OLED の設定メニューにあります。復帰には、PC がスリープ中も USB に給電し続ける必要があります。
- **トリガーエフェクトの強さ、スピーカーブースト、音量をロック、マイクとスピーカーの選択、ステータスピン（アップストリームの設定、プロトコル 1.13）** — アダプティブトリガーを 10 段階で弱める（デフォルトはゲーム本来の強さ）、コントローラーのアンプのプリゲイン、ゲームによるコントローラー音量の変更を防ぐ、マイクを 自動／内蔵／ヘッドセット から選択、PC の音声出力を 自動／スピーカー／ヘッドセット／オフ から選択、コントローラーの接続状態を示す GPIO。MUTEボタンのランプがマイクのミュートに連動し、PC のミュートとマイクレベルがコントローラーに届きます。新しい設定は 500 Hz でポーリングします。
- **4 スロットの保存される複数コントローラーペアリング** — 最大 4 台の DualSense を登録し、OLED から切り替え。起動時にスロット 0 に自動で再接続
- **ライトバーカラーピッカー**、4 つのお気に入りスロット + ブリージング／レインボー／フェードのエフェクトプリセット
- **保存される設定メニュー**（OLED）：6 つのグループ（ハプティクスとトリガー、オーディオ、接続、画面とライト、PC のスリープ）に 25 の設定と、長押しで確定する Reset to defaults・Wipe all slots の操作
- **OLED のアイドル時省電力段階** — 手動の明るさ切り替え（KEY1 長押し）、2 分間操作がないと小さな呼吸ドットを残して自動で大きく減光、15 分で表示を完全にオフ。ボタン、コントローラーのペアリング、入力ですぐに復帰します。コントラストの調整だけでなく、本当の焼き付け防止です。
- **ソフトリブート**：USB を抜かずに、DS5 の `PS + Mute` 長押し（画面なしでも動作）、または OLED アドオンの **KEY0 + KEY1 を 1 秒同時押し**（以前の KEY0 ダブルクリックの代わり。素早くページを送ると誤って発動しやすかったため）
- **クリアなコントローラーのスピーカーとマイク** — core1 のオーディオ経路（Opus、リサンプラー、メモリ操作）を RAM から実行し、音声はアップストリームのパックされた `0x39` レポートで送られ、マイクは core1 でデコードされてホストの USB クロックに合わせて送り出されます。これにより、長年のスピーカーのノイズとマイクオン時の途切れが解消されました（[CHANGELOG.md](./CHANGELOG.md) を参照）。**[awalol](https://github.com/awalol/DS5Dongle) に感謝**：これはアップストリームのオーディオの成果を移植したものです。
- **コアブリッジの監査** — オーディオ経路の重大なスタックオーバーフローの修正（長年の「音声の途切れ」を解消）、セキュリティ強化、ウォッチドッグ、HID/L2CAP の境界での長さ検証（[CHANGELOG.md](./CHANGELOG.md) を参照）

## 🐧 Linux：ネイティブのアダプティブトリガー（Proton）

Linux でゲームに **ボード経由でコントローラーのアダプティブトリガー** を動かさせるには、Wine の `winebus.sys` **#9034** の修正を含む Proton が必要です。公式の **GE-Proton 11** リリースには現在この修正が含まれています。ここで提供しているビルド **`GE-Proton11-7.2-DualSense`**（[そのリリース](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Edition/releases/tag/proton-GE-Proton11-7.2-DualSense)を参照）は、公式の `GE-Proton11-7` に `winebus.sys` の修正を 1 つ加えたものです：DualSense はシリアル番号をコロン区切りの Bluetooth MAC として報告するため、Windows ではそのデバイスパスを開けず、Sony の libScePad を使うゲームはトリガーに届きません。このビルドはその文字を置き換えてパスを開けるようにします。また、`PROTON_PREFER_SDL=1` を設定すると、XInput 専用のゲームでもコントローラーを標準のゲームパッドとして振動付きで使えます（[変更履歴](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Config-Web/blob/master/docs/PROTON_CHANGELOG.md)）。下記のトリガーの結果は 1 つ前のビルド GE-Proton11-7-DualSense で検証したもので、ネイティブ経路は変わっていません。

> 理由：#9034 のバグは、同じ VID/PID の hidraw デバイスが存在するときに SDL のゲームパッドデバイスを抑制するため、パッドは *ゲーム内以外のどこでも* 認識されます。修正により、ネイティブ（トリガー対応）の経路と動作するゲームパッドが共存できます。

**最初の一度だけの設定**

1. **Proton ビルドをインストールします。** [リリース](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Edition/releases/tag/proton-GE-Proton11-7.2-DualSense)から `GE-Proton11-7.2-DualSense.tar.gz` をダウンロードし、次の場所に展開します：
   - **Steam：** `~/.steam/root/compatibilitytools.d/`
   - **Heroic：** `~/.config/heroic/tools/proton/`

   その後、新しい互換性ツールを認識させるために **Steam を完全に再起動** します。
2. **Steam Input を無効にして**、ゲームがコントローラーとネイティブに通信するようにします — Steam → ゲームの **プロパティ → コントローラー → Steam Input を無効化**（または全体で：設定 → コントローラー → PlayStation コントローラーのサポートをオフ）。

**ゲームごと**

3. **Proton を強制します：** Steam → ゲームを右クリック → **プロパティ → 互換性 → 特定の Steam Play 互換性ツールの使用を強制する → `GE-Proton11-7.2-DualSense`**。（Heroic：ゲームの *Wine バージョン* をこれに設定します。）

**起動オプションは不要です** — Wine 11 は hidraw のネイティブ経路をデフォルトで有効にするため、ボードは自動的にゲームに渡されます。起動するだけで、ボード経由でネイティブのアダプティブトリガーが動作し、有線の DualSense と 1:1 で同じです（フラグなしで検証済み：Cyberpunk 2077、Uncharted、Spider-Man Remastered、The Last of Us Part I、Avatar、Indiana Jones、Star Wars: Galactic Racer — **Steam と Heroic の両方** で）。ゲームが **DualSense にネイティブ対応** している必要があります（XInput 専用のゲームでは振動は出ますがアダプティブトリガーは動きません — これはエンジンの制限で、ボードの問題ではありません）。新しい Proton での初回起動ではロケールとプレフィックスの準備が行われ、1 分ほど「応答なし」になることがあります — これは準備中であってクラッシュではありません。終わるまで待ってください。

**コントローラーのオーディオはデフォルトのプロファイルのままにしてください。** GE-Proton 11 は DualSense のハプティクスを自分で振り分け、カードが標準の **HiFi** プロファイルであることを前提にしています。DualSense を **pro-audio** に強制する WirePlumber/PulseAudio のルール（古い Proton ビルド向けによく紹介される方法）を使うと、Avatar がトリガーに力ゼロを送り、HD ハプティクスが失われました（検証済み。Sony が移植したほかのゲームも同様の可能性が高いです）。そのようなルールは削除するか、`pactl list cards` で DualSense が `Active Profile: HiFi (...)` と表示されることを確認してください。

### Heroic（Epic／GOG）— 同じ手順に、追加の条件が 2 つ

ネイティブのトリガーは Heroic でも同じように動作しますが、Steam 以外のランチャーは、気づかないうちにコントローラーを奪う 2 つのホスト側の要因に影響されます：

1. **Steam を完全に終了します** — バックグラウンドの Steam は Steam 以外のゲームから DualSense を奪います（または 設定 → コントローラー → PlayStation コントローラーのサポート を無効にします）。
2. **`PROTON_PREFER_SDL` を全体に設定しないでください** — この環境変数は SDL/Xbox の経路を強制し、ネイティブのトリガーを *抑制* します。汎用パッドへの意図的なフォールバックとして、ゲームごとにのみ使ってください。

**起動オプションの参考**

| 変数 | 値 | 目的 |
|---|---|---|
| `PROTON_ENABLE_HIDRAW` | `0x054c/0x0ce6` | *旧来／オプション — Wine 11 では **不要***。Wine 11 は hidraw のネイティブ経路をデフォルトで有効にします。設定しても害はありません。hidraw がオプトインだった古い Proton でのみ関係します（ただしそれらは #9034 の修正もないため、いずれにしてもトリガーは動きません）。 |
| `PROTON_PREFER_SDL` | `1` | *代替、入力のみ。* SDL のゲームパッド経路を強制します — 入力と振動は動きますが、汎用／Xbox パッドとして扱われます（**トリガーなし**）。ゲームが DualSense にネイティブ対応しておらず、`ENABLE_HIDRAW` でも解決しない場合にのみ使ってください。トリガー対応ゲームでは `ENABLE_HIDRAW` と組み合わせ **ないで** ください。これを尊重する Proton が必要です：**GE-Proton11-7.2-DualSense** は対応しています（アプリの **ゲーム** ページが XInput 専用ゲームに設定します）。古い GE-Proton11-7-DualSense はこれを無視します。 |
| `PROTON_LOG` | `+hid` | *診断専用*（通常のプレイ向けではありません）。HID の列挙トレースを書き出します — Steam では `~/steam-<appid>.log` に、Heroic は `PROTON_LOG_DIR` をホームに設定するため `~/steam-0.log` に出力されます。ゲームがネイティブの HID 経路を開いたことを確認するのに便利です。 |

> **Heroic と Steam の違い：** ネイティブのトリガーは **両方** で動作し、Wine 11 ではどちらも起動オプションは不要です。Steam：ランナーを設定し、Steam Input を無効化。Heroic：ランナーを設定し、**Steam を完全に終了**（バックグラウンドの Steam は Steam 以外のゲームからパッドを奪います）、`PROTON_PREFER_SDL` はオフのままにします。いずれの場合も、ゲームが DualSense にネイティブ対応している必要があります — XInput 専用のゲーム（例：Ghostrunner、Control）は、どの OS でも振動は出ますがアダプティブトリガーは動きません。それらのゲームには `PROTON_PREFER_SDL=1` と、**GE-Proton11-7.2-DualSense** のようにそれを尊重する Proton ビルドが必要です。

## はじめに

### ファームウェアの書き込み

[アプリ](#️-はじめにアプリをダウンロード)が自動で行います。手動で書き込む場合（または CI の成果物である Pico W ビルドの場合）：

1. Pico2W の BOOTSEL ボタンを押し続けます
2. USB で Pico2W をパソコンに接続します
3. デバイスが USB ストレージとしてマウントされます
4. .uf2 ファームウェアファイル（[リリース](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Edition/releases)から）をデバイスにドラッグ＆ドロップします

### コントローラーのペアリング

1. DualSense コントローラーを Bluetooth ペアリングモードにします
2. Pico2W が検出して接続するのを待ちます
3. 接続されると、デバイスがホストシステムに表示されます

## 設定

ファームウェアを設定する方法は 4 つあります：

**設定アプリ（推奨）：** Linux、Windows、macOS 向けの [DS5 Dongle OLED Edition Configurator](#️-はじめにアプリをダウンロード)（**ゲーム** ページには Linux では Steam、Heroic、Lutris のゲームが、Windows では Steam、GOG Galaxy、Epic のゲームが表示され、Proton の設定は Linux のみです）。ボードを自動的に見つけ、変更をすぐに反映し、ワンクリックでボードのフラッシュに保存します。ファームウェア v0.8 以降が必要です。

**本体（OLED アドオンあり）：** 画面上の **Settings** メニュー（11 番目の画面）を使います。方向キー ▲▼ で選択を移動、✕ でグループを開き ○ で戻る、▶◀ で値を調整、△ でフラッシュに保存します。

**ターミナル CLI（任意の OS、任意のブラウザー）：** hidapi をインストールし、`scripts/set_ds5.py` を使います：

```bash
pip install hidapi
scripts/set_ds5.py                            # 現在の設定を表示
scripts/set_ds5.py --auto-haptics fallback    # 項目を変更してフラッシュに保存
scripts/set_ds5.py --speaker-volume -10 --haptics-gain 1.5
scripts/set_ds5.py --slot 2                   # 有効なペアリングスロットを切り替え
scripts/set_ds5.py --version                  # ファームウェアのバージョン
scripts/set_ds5.py --rssi                     # BT の信号をライブ表示（理想範囲を基準にした dB、0 = 理想）
scripts/set_ds5.py --help                     # すべてのフラグの一覧
```

このスクリプトは USB HID の feature レポート `0xF6`/`0xF7`/`0xF8`/`0xF9` でファームウェアと通信します。v0.6.12 以降、これらのレポートは HID ディスクリプターで宣言されていないため（ゲームは本物の DualSense とバイト単位で同じディスクリプターを必要とします）、スクリプトは Linux でのみ動作します。ほかの OS では設定アプリを使ってください。[loteran/DS5Dongle](https://github.com/loteran/DS5Dongle) から移植し、このフォークの `current_slot` 項目向けに拡張しています。

**DualSense コントローラーのボタン（旧来の代替手段、OLED なし、CLI なし）：**

### マイク音量

ハプティクスゲインの倍率を調整します。範囲：`[1.0 – 2.0]`。

### スピーカーのミュート

LED による接続表示を無効にします。コントローラーの再接続後に有効になります。

### マイクのミュート

サイレント切断の動作を無効にします。

## 注意事項

Pico デバイスは、コントローラーが接続された後にのみシステムから見えるようになります

一部の動作は、再接続を経てから有効になります

### バッテリー残量低下の LED 表示

接続中の DualSense のバッテリーが 10% 以下（かつ充電中でない）と報告されると、Pico のオンボード LED が点灯から 1 Hz の点滅に切り替わり、ひと目で警告がわかります。コントローラーを充電ケーブルにつなぐか、報告される残量が再び上がると、LED は点灯に戻ります。`disable_pico_led` が設定されていても点滅します — この警告は重要とみなされ、LED オフの設定より優先されます。バッテリーが回復するかコントローラーが充電を始めると、LED は無効（消灯）の状態に戻ります。

ビルド時に無効にするには、`-DENABLE_BATT_LED=OFF` で設定します。デフォルトは ON です。

## Bluetooth での DualSense のマイク

**DualSense の内蔵マイクは、ボードとの Bluetooth ペアリングで動作します**（v0.6.8 以降）。コントローラーはマイクの音声を Opus で送り、ボードがそれをデコードして、標準の DualSense USB キャプチャーデバイスとしてホストに提供します。そのため、どのアプリ（Discord、OBS、ゲーム内ボイスチャット）でも通常のマイクとして使えます。

これは長い間不可能だと考えられていました — このフォークの以前のバージョンでは、Sony のファームウェアによる絶対的な制限として記載していました（Linux の `hid-playstation` カーネルドライバーは今も対応していません）。実際には、ボードが送るオーディオレポートの 1 つの有効化ビットだけが鍵でした。**これを突き止めた [awalol](https://github.com/awalol/DS5Dongle)（アップストリーム）に全面的に感謝します。** 訂正済みの調査記録は [BLUETOOTH_AUDIO_NOTES.md](./BLUETOOTH_AUDIO_NOTES.md) にあります。

**使い方：**

- **デフォルトでオン。** コントローラーをペアリングすると 1〜2 秒でマイクの送信が始まります — ゲームの音声は不要です（ボードが自分でストリームを維持します）。
- **ホスト側でキャプチャー音量を上げてください** — デフォルトでは低めです。Linux では `arecord -l` でカードを探し、例えば `amixer -c <DualSense card> sset 'Headset' 90%` を実行します。`scripts/mic_diag.sh capture` でキャプチャーを確認できます。
- **コントローラーのバッテリーを節約するにはオフに** — OLED の **Settings → Audio → Built-in mic**、または[設定アプリ](#️-はじめにアプリをダウンロード)の **内蔵マイク** スイッチで切り替えます。マイクを常にオンにすると DS5 のオーディオ回路が動き続け、バッテリーの消耗が目に見えて早くなるため、ボイスチャットを使わない場合はオフにしてください。

**注意点：**

- マイクの音声は **モノラル** です（モノラルでデコードし、ステレオのキャプチャーエンドポイントの両方に複製）。
- 使用中にオフにするとホストへの送信はすぐに止まりますが、コントローラーは次に再接続するまで送信を続けます（「停止」コマンドは知られていません）。オフの状態で新たに接続した場合は、有効になりません。
- OLED の **Diagnostics** 画面の `Mic in:` カウンターは、マイクの送信中は約 100/s を示します — 動作しているかを素早く確認できます。
- **パケットロスの補完：** 失われたマイクのフレーム（弱い BT リンク、距離、干渉）は Opus PLC で補完されるため、音声はブツブツ途切れずに続きます。代わりにわずかなジッターバッファーの遅延（約 30 ms）が生じます。Diag 画面の `Mic PLC:` カウンターは、フレームが補完されているときだけ増えます — 実質的にリンク品質のライブ表示です。

## 既知の問題

- Linux + Steam では、HD ハプティクスがすべてのゲームで動作するとは限りません。これはゲーム側の問題です（一部のタイトルは Windows 固有の API でのみ HD ハプティクスの音声を送ります）。Spider-Man Remastered では動作を確認済み、Ghost of Tsushima では届きません — 同じファームウェア、同じコントローラーです。
- **USB 3.0 ポートはペアリングを妨げることがあります** — コントローラーのライトバーがオレンジ／黄色の点灯のまま接続されないことがありますが、同じボードを USB 2.0 ポートにつなぐと問題なく動作します。これはファームウェアのバグではなく電波干渉です。下の [USB 3.0 ポートと Bluetooth の干渉](#usb-30-ポートと-bluetooth-の干渉)を参照してください。（v0.6.8 以降、ファームウェアは止まった接続で固まらずに自動で再試行するため、多くの — すべてではありませんが — ぎりぎりのケースは回復します。）
- **Windows：アプリがボードを開けない** ことがあります。以前に本物の DualSense を USB で接続したことがある PC で起こります（ボードは同じ USB ID を使い、Windows はその ID に「ドライバー不要」を記憶しています）。アプリ 0.9.2 以降、セットアップ画面に **USB ドライバーを修復** があります：管理者の確認が 1 回、その後に挿し直します。実行される PowerShell の全文は、1 行ずつ[アプリの README](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Config-Web#repair-usb-driver-exactly-what-it-runs) にあります。

## USB 3.0 ポートと Bluetooth の干渉

ボードがあるポートでは動作し、別のポートでは動作しない場合は、**まず USB 2.0 ポートを試してください。** USB 3.0 ポートと（特に）USB 3.0 延長ケーブルは、2.4 GHz 付近を中心とする広帯域の電波ノイズを出します — これはボードの Bluetooth 無線がコントローラーとの通信に使う帯域と同じです。これは業界でよく知られた問題であり（Intel、*"USB 3.0 Radio Frequency Interference Impact on 2.4 GHz Wireless Devices"*）、このファームウェアに固有のものではありません。ノイズでボードの BT 受信感度が下がるため、コントローラーは接続を始められても（オレンジのライトバー）、リンクのノイズが多すぎて接続を完了できず — 黄色のまま止まります。

対策（おおむね効果の高い順）：

1. **ボードを USB 2.0 ポートに挿します**（多くの場合いちばん簡単な解決策 — 多くのマザーボードやケースには両方あります）。
2. **短い USB 2.0 延長ケーブルを使い**、ボードを USB 3.0 ポートや金属製の筐体から数 cm〜十数 cm 離して、コントローラーとの見通しを良くします。USB 3.0 延長ケーブルは特に避けてください。
3. USB 3.0 ポートに **セルフパワーの USB 2.0 ハブ** をつなぎます — ハブがリンク速度を下げ、距離も確保できます。
4. ボードの近くでケーブルに **フェライトコアを取り付けます**。
5. ペアリング中は **コントローラーをボードの近くに、見通しの良い位置に置きます**。

ファームウェアは止まった接続を自分で再試行し続けるため、ライトバーがオレンジになってから 10〜20 秒ほど挿したままにしておくと、挿し直さずに回復することがあります。

## パフォーマンス / クロック

**これについて何もする必要はありません。** Pico 2 W はアップストリーム awalol/DS5Dongle v0.7.0 と同じ設定で動作します：

- **クロック：150 MHz**、RP2350 の定格クロック（起動時のクロック）
- **コア電圧：1.10 V**、デフォルト値。RP2350 は電源を抜くまで以前のファームウェアの電圧を保持するため、ファームウェアが起動時に設定します。
- **Bluetooth チップのバス（CYW43 PIO SPI）：クロック分周 2**
- **フラッシュ：75 MHz**（分周 2）、起動時にファームウェア自身が設定します（`PICO_EMBED_XIP_SETUP`）。bootrom の設定のままにすると、一部のボードで core1 がクラッシュしました（[issue #15](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Edition/issues/15)）。

以前のリリースは、アップストリームから引き継いだ設定で 1.20 V・320 MHz にオーバークロックしていました。アップストリームはオーディオ経路を RAM から実行するようになって 150 MHz に移行し、このフォークもオーディオ経路と core0 の Bluetooth/USB のホットパスの両方を RAM から実行するようになったため同様に移行しました。1.20 V は RP2350 の動作上限 1.16 V を超えており、150 MHz ではヒートシンクは不要です。

1 リリースの間だけ、ソースからのビルドでは古いオーバークロックをフォールバックとして使えます：`-DDS5_CLOCK_KHZ=320000`（1.20 V、Bluetooth バス分周 5、フラッシュ分周 4）。組み込みのフラッシュ設定がない Pico 2 W の構成や、フラッシュが 100 MHz を超える構成はビルドが拒否します。Pico W ビルドは変更ありません（200 MHz）。

## ビルド手順

ソースからプロジェクトをビルドするには：

1. Pico SDK **2.3.0** をインストールします。ビルドは `pico_sdk_import.cmake` を使います。CI とリリースは ARM 公式の GNU ツールチェーン **15.2.Rel1**（`arm-none-eabi`）でビルドしています。ディストリビューションの `gcc-arm-none-eabi` でも通常は動作しますが、15.2.Rel1 ならリリースと同じバイナリになります。正確な固定バージョン（SDK、TinyUSB のコミット、ツールチェーンのダウンロード先）は `tools/toolchain.env` にあります。ツールチェーンが `PATH` にない場合は、`PICO_TOOLCHAIN_PATH` を展開したツールチェーンのフォルダーに設定してください。
2. Pico SDK 内（`$PICO_SDK_PATH/lib/tinyusb`）で **TinyUSB を `tools/toolchain.env` のコミットに固定します**：アップストリームと同じく、TinyUSB 0.21 にその後の修正を加えたものです。Pico SDK 2.3.0 はまだ 0.18.0 を同梱しており、このプロジェクトの `tusb_config.h` が使う `TUD_AUDIO_EP_SIZE` の 4 引数形式がありません。また、ビルドは 0.21 以外の TinyUSB を拒否します：
   ```bash
   cd "$PICO_SDK_PATH/lib/tinyusb"
   git fetch --depth 1 origin 2d56dc533e45e4e91b15e93fdab5e22e964f328d
   git checkout --detach FETCH_HEAD
   ```
3. CMake + Ninja（または Make）で設定してビルドします：
   ```bash
   cd /path/to/DS5Dongle
   cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DPICO_SDK_PATH="$PICO_SDK_PATH"
   cmake --build build --target ds5-bridge
   ```
4. UF2 は `build/ds5-bridge-oled.uf2` に出力されます。いつもどおり BOOTSEL で書き込みます。

知っておくと便利なビルドフラグ：

- `-DENABLE_BATT_LED=ON`（デフォルト）— DS5 のバッテリー残量が少ないとき Pico の LED を点滅させます。
- `-DENABLE_SERIAL=ON` — デバッグ用に printf を USB CDC に出力します（デフォルト OFF。製品ビルドでは UART を解放します）。
- `-DPICO_W_BUILD=ON` — 初代 Pico W 向けにビルドします（オーディオなし、クロックを下げます）。デフォルトは Pico 2 W 向けです。

## 診断とデバッグツール

ブリッジの問題を切り分ける方法は 2 つあります — 本体側は OLED の Diagnostics 画面、ホスト側は `scripts/mic_diag.sh`（Linux）です。ホスト側のほうが速く、画面の切り替えも書き込みのやり直しも不要で、コントローラーを使っている最中に実行できます。

```
# 1 回だけのスナップショット — ボードは USB 上にあるか？ALSA は認識したか？
# キャプチャーストリームは動いているか？コントローラーは今ペアリングされているか？
scripts/mic_diag.sh status

# マイクの IN エンドポイントで 3 秒間 arecord — ピーク / RMS / 非ゼロ数を報告し、
# 「ストリームが無音」か「ストリームが音声を出している」かを区別します。
scripts/mic_diag.sh capture 3

# `status` と同じですがループで実行し、状態が変わったときだけ表示します。
# ペアリングの完了やオーディオストリームの開閉の正確な瞬間をとらえるのに便利です。
scripts/mic_diag.sh watch

# ファームウェアの 0xFD ベンダー feature レポートをライブで読み取ります（/dev/hidraw 経由）：
# BT 入力の数とレート、最後に見た 0x31 以外の ID、バイトの先頭、そして
# トリガーの流れのカウンター（受信したホストの 0x02 / AllowTriggerFFB が立っているもの /
# BT に転送したもの）。bt-trace は判定を表示します —「ホストのドライバーが
# トリガーの Allow ビットを送っていない」か「転送したがコントローラーが動かなかった」か —
# 本来なら USB プロトコルアナライザーが必要な判断です。
scripts/mic_diag.sh bt-trace
```

もともとは、保留中の DS5 BT マイクの調査を切り分けるために書いたものです（[BLUETOOTH_AUDIO_NOTES.md](./BLUETOOTH_AUDIO_NOTES.md) を参照）。`0xFD` feature レポートと `bt-trace` のデコーダーは現在、[issue #3](https://github.com/MarcelineVPQ/DS5Dongle-OLED-Edition/issues/3)（一部のゲームでアダプティブトリガーの抵抗がない問題）のために追加したトリガーの流れのカウンターも扱います。

## OLED ディスプレイアドオン（オプション）

[Waveshare Pico-OLED-1.3](#ハードウェア) を Pico2W のヘッダーに差し込むと、ファームウェアが自動的にライブのステータス表示として駆動します。設定は不要です — OLED がない場合、ファームウェアは何もせず問題なく動作します。

<img src="./assets/oled/oled-status-live.gif" alt="OLED でライブ表示中のステータス画面" width="512">

実機ボードで動作中のステータス画面を、OLED ミラー経由でピクセル単位でキャプチャしたものです。以下の各画面の画像もすべて実機からのキャプチャです。

### 起動画面（電源投入時に 1.5 秒）

空白の画面の中央にファームウェアのバージョンを 1.5 秒表示し、その後ステータス画面に移ります。

### 11 の画面、アドオンの KEY0 で切り替え

切り替え順：**Status → Slots → Lightbar → Trigger Test → Gyro Tilt → Touchpad → Diagnostics → CPU/Clock → BT Signal → VU Meters → Settings →** 最初に戻る。**KEY0 の短押しで次へ、KEY1 の短押しで前へ** — *すべての* 画面で同じです。画面ごとの操作（トリガープリセットの切り替え、ライトバーのモードの切り替え、Settings のカーソル移動、スロットの切り替え）は **DualSense コントローラーのボタン** で行い、KEY0/KEY1 には割り当てません。そのため OLED アドオンの 2 つの物理ボタンは常に同じ意味です。

どの画面でも左上の端（KEY0 の横）に **`>`**、左下の端（KEY1 の横）に **`<`** を表示し、画面上のラベルと物理ボタンが対応するようにしています。

#### 1. ステータス

接続状態、ペアリング中の DualSense の BD アドレス、バー付きのバッテリー残量 %（`+` 充電中 / `*` 充電完了 / `!` エラー）、アナログスティックの位置のライブ表示（**L3 / R3** を押し込んでいる間、そのスティックの枠が反転表示で点滅します — 白い枠に黒い点）、方向キー、アクションボタン（△ ◯ ✕ □）、L1/R1、L2/R2 のアナログトリガーの塗りつぶしバー。リンク表示とバッテリーは小さなピクセルアイコンです。充電中は、100% までの推定時間 `~Nm` がバッテリーの横に表示されます。

<img src="./assets/oled/oled_sc01.png" alt="OLED のステータス画面" width="512">

#### 2. スロット

保存される 4 スロットの複数コントローラーペアリング。登録済みのコントローラーを閲覧し、有効なスロットを切り替え、または 1 つのスロットを消去します。`>` はカーソル、`*` は現在有効なスロットを示します。

<img src="./assets/oled/oled_sc02.png" alt="OLED のスロット画面" width="512">

- **方向キー ▲▼** — スロット 0〜3 の間でカーソルを移動
- **△** — カーソルのスロットに切り替え（現在の接続を切り、そのスロットに登録されたコントローラーに再接続）
- **□ を 1.5 秒長押し** — カーソルのスロットを消去（bd_addr と BTstack のリンクキーを削除）
- 有効なスロットは保存され、次回の起動時にボードがそのスロットに再接続します

#### 3. ライトバーカラーピッカー

コントローラーを各軸に傾けて R / G / B を調整します。ファームウェアは 10 Hz で結果の色を DualSense の実際のライトバーに送るため、ライトバーそのものがプレビューになります（OLED はモノクロです）。

<img src="./assets/oled/oled_sc03.png" alt="OLED のライトバーカラーピッカー" width="512">

- コントローラーの **△ ◯ ✕ □** を押すと、現在の色をお気に入りスロット 0 / 1 / 2 / 3 に **保存** します
- コントローラーの **R1** を押すとモードのタグが切り替わります：`[LIVE]` → `[FAV0]` → `[FAV1]` → `[FAV2]` → `[FAV3]` → エフェクト（Breathing / Rainbow / Fade）→ `[HOST]` → `[LIVE]` に戻る
- `[HOST]`（デフォルト）はライトバーを PC／ゲームに任せ、ボードは色を設定しません。ほかのモードでは、ゲームが何を送ってもボードの色を保ちます
- デフォルトのお気に入り：赤、緑、青、白

#### 4. トリガーテスト

コントローラーの **△** を押すと、L2 と R2 の両方にかかる 7 種類のアダプティブトリガーのエフェクトが切り替わります。各トリガーを引いてエフェクトを感じてください。

<img src="./assets/oled/oled_sc04.png" alt="OLED のトリガーテスト画面" width="512">

切り替え順：**Off → Feedback → Weapon → Vibration → Bow → Gallop → Machine Gun → Off …** エフェクトのパラメーターは [dualsensectl](https://github.com/nowrep/dualsensectl) のリバースエンジニアリングに従ってビット単位で詰めたもので、すべて最大の強さです。

#### 5. ジャイロ傾き

加速度センサーの X/Y/Z の値と 40×40 の十字の枠をライブ表示します。点はコントローラーの傾きをリアルタイムで追い、**コントローラーを平らに置くと中央に来ます** — コントローラー自身の個体ごとの工場出荷時 IMU キャリブレーション（feature レポート `0x05` から読み取り）を使うため、静止位置とゲインはどのコントローラーでも正確です。左右・前後に傾けると、点が同じ方向に動きます。

<img src="./assets/oled/oled_sc05.png" alt="OLED のジャイロ傾き画面" width="512">

#### 6. タッチパッド

タッチパッドの表面をライブで描画します。指の位置に点が表示され、指が触れたり離れたりすると数が更新されます。

<img src="./assets/oled/oled_sc06.png" alt="OLED のタッチパッド画面" width="512">

#### 7. 診断

スクロールできるライブのカウンター一覧 — 稼働時間、BT の状態、ホスト → BT のトリガーの流れ（`host02` / `trig` / `tx`）、BT 0x31 入力のレート、USB オーディオのフレーム数／秒、BT 0x32 のパケット数／秒、そして一番下に保留中のマイク調査のカウンター。コントローラーの方向キー ▲/▼ でスクロールし、右端の小さな `^` / `v` が「上／下にまだある」ことを示します。読み取り専用なのでカーソルはありません。UART ケーブルなしでブリッジがバイトを運んでいることを確認するのに便利です。

同じカウンターはホスト側のツール向けに HID の feature レポート `0xFD` でも出力されます — 下の `scripts/mic_diag.sh bt-trace` を参照してください。

<img src="./assets/oled/oled_sc07.png" alt="OLED の診断画面" width="512">

#### 8. CPU / クロック

RP2350 のライブの状態：設定値（`Set`）と実際に動作している（`Real`）システムクロック（水晶の基準で計測）、レギュレーターから読み戻したコア電圧、チップの温度（256 サンプルの平均 + 緩やかな EMA で、ADC のノイズではなく実際のチップの温度に追従します）。

<img src="./assets/oled/oled_sc08.png" alt="OLED の CPU / クロック診断画面" width="512">

同じテレメトリーはツール向けに HID の feature レポート `0xFC` でも出力されます。

#### 9. BT 信号

有効なリンクの Bluetooth 信号強度を、理想範囲を基準にした dB でライブ表示します（0 = 理想で *in range* と表示、マイナスが大きいほど弱い）。バーは −30 dB で空、0 dB で満杯です。アプリと同じラベル（Excellent / Good / Fair / Weak、つまり非常に良好 / 良好 / 普通 / 弱い）付きです。最初の測定の前や測定に失敗したときは `Signal: --` と `Link: unknown` を表示します。

<img src="./assets/oled/oled_sc09.png" alt="OLED の BT 信号画面" width="512">

#### 10. VU メーター

スピーカーとハプティクスのオーディオ経路のピークメーターをライブ表示します。コントローラーをホストにつながずにオーディオの経路を確認するのに便利です。

<img src="./assets/oled/oled_sc10.png" alt="OLED の VU メーター画面" width="512">

#### 11. 設定

保存される設定エディター。6 つのグループのメニューで開き、それぞれに含まれる設定の数が表示されます：**Haptics/trigger**、**Audio**、**Connection**、**Screen & lights**、**PC sleep**、**Reset**。方向キー ▲▼ で選択を移動し、✕（または ▶）でグループを開き、○ でメニューの元の位置に戻ります。グループ内では ▶◀ で値を調整します。△ はどこからでもフラッシュに保存します。選択中の行は明るいバーで表示され、変更してまだ保存していない値はそのバーの中の暗い窓に表示され、保存するまでタイトルに `(*)` が付きます。

<img src="./assets/oled/oled_sc11.png" alt="OLED の設定画面" width="512">

- **Haptics/trigger：** `Vibration L` と `Vibration R`（左右それぞれの振動の強さ）、`Trig. effect`（トリガーエフェクトの強さ：`game` はゲーム本来の強さ、-1〜-10 で弱く）、`AutoHap`（Audio Auto Haptics のモード、下記）、`AutoHap gain`（0〜200 %、10 % 刻み、デフォルト 100 %）、`Auto filter`（エンベロープ追従の前のローパスのカットオフ、80 / 160 / 250 / 400 Hz、デフォルト 160 Hz：低いほど重低音が増えます）。
- **Audio：** `Spk volume`、`Spk boost`（スピーカーブースト、コントローラーのアンプのプリゲイン：`game` はゲームに任せる、または 1〜7）、`Lock volume`（ゲームはコントローラーのスピーカー、ヘッドセット、マイクの音量、ミュート、ミュートランプを変更できません。PC 自身の音量とミュートは引き続き反映されます）、`Audio out`（Auto / SPK / Hset / off：PC の音声をどこで再生するか。Auto = コントローラーにヘッドセットが接続されていればヘッドセット）、`Built-in mic`（マイクをオフにするスイッチ）、`Mic used`（Auto / Int / Hset）、`Mic level`（`PC` は PC のマイクレベルに従う、または 1〜64）、`Echo cancel`、`Audio buffer`（32〜128）。
- **Connection：** `Controller`（DS5 / DSE / Auto）、`Poll rate`（250Hz / 500Hz / RT）、`Disconnect`（操作のないコントローラーを切断）、`Idle time`（10〜60 分）。
- **Screen & lights：** `Screen dim` と `Screen off`（分。`off` = しない）、`Wake on input`（コントローラーの操作で画面を復帰）、`Status LED`（Pico の LED）。
- **PC sleep：** `Turn off ctrl`（PC が 3 秒スリープするとコントローラーの電源を切る、デフォルトはオン）、`PS wakes PC`（コントローラーが接続されていないとき、ボードが復帰専用キーボード「DS5 Dongle Wake Keyboard」として認識され、PS ボタンで PC を復帰できます。デフォルトはオフ）。
- **Reset：** `Reset to defaults`（△ を 2 秒長押し。すべての設定を元に戻し、現在のスロットは残します）、`Wipe all slots`（△ を 2 秒長押し。ペアリング済みの 4 台のコントローラーとすべての BTstack のリンクキーを削除）。

`AutoHap` のモード：`Off`（デフォルト）はハプティクスをゲームからのみ受け取ります。`Fallback` はゲームがネイティブのハプティクスデータを送らないときだけ（例：Linux の Ghost of Tsushima）派生した振動を出します。音楽やデスクトップの音声に合わせても振動する点に注意してください。ネイティブのハプティクスを *送る* ゲーム（Spider-Man Remastered）はそのまま通します。`Mix` はネイティブに派生した振動を重ね、`Replace` はネイティブを完全に無視します。

### ボタンの一覧

OLED アドオンの 2 つの物理ボタンは **ナビゲーション専用** です：

| ボタン | 動作 |
|---|---|
| **KEY0** 短押し | 次の画面（前へ進む） |
| **KEY1** 短押し | 前の画面（戻る） |
| **KEY1** 1.5 秒を超えて押し続ける | 押している間に明るさを 1 段階切り替え、離しても戻らない |
| **KEY0 + KEY1** を 1 秒以上同時押し | `watchdog_reboot` — USB を抜かずにソフトリブート |

画面ごとの状態の変更（トリガープリセットの切り替え、ライトバーのモードの切り替え、Settings の操作、スロットの切り替え、色をお気に入りスロットに保存）はすべて **DualSense コントローラーのボタン** で行います — KEY0 / KEY1 では行いません — そのため 2 つの物理ボタンはどの画面でも常に同じ意味です。どのコントローラーのボタンが何をするかは、上の各画面の説明を参照してください。

### ピン配置（標準の Waveshare Pico HAT レイアウト）

| 機能 | GPIO |
|---|---|
| MOSI | 11 |
| SCK  | 10 |
| CS   | 9  |
| DC   | 8  |
| RST  | 12 |
| KEY0 | 15 |
| KEY1 | 17 |

### ソフトリブートによる復旧

USB を抜かずにボードを再起動する方法は 2 つあります — ペアリングが止まったときや、きれいな状態に戻したいときに便利です：

- **OLED の KEY0 + KEY1 を 1 秒以上同時押し** → `watchdog_reboot`。以前のバージョンの「KEY0 ダブルクリック」の代わりです。素早く画面を送ると、ダブルクリックの判定が誤って発動していたためです。
- **DualSense の `PS + Mute` を 2 秒長押し** → `watchdog_reboot`（OLED の有無にかかわらず動作します — 画面なしの予備手段）。
